# Karwan

Use `references/product.md` for product claims, `references/wallets.md` for identity and money movement, and `references/testing.md` before proposing or evaluating a workflow.

For any product walkthrough, transaction plan, integration, support answer, or end-to-end test, read `references/full-product-usage.md` completely before acting. Follow its financing selection rules, account variants, ordered examples, and evidence requirements.

For a bug report, a feedback item, or an "improve X" request, read `references/build-shape.md` first. It maps a reported symptom to every layer that has to change, so a fix lands everywhere it belongs instead of only where the screenshot pointed.

Do not invent capabilities, numbers, addresses, or production status. Treat testnet behavior as testnet behavior. Separate identity, signing wallets, custody, and settlement. For money-moving work, require simulation, an on-chain receipt, decoded transfers, contract state, and the matching database projection before calling it complete.

When a request conflicts with a reference, state the conflict and ask for an updated canon entry instead of guessing.
