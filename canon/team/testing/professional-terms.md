Use precise language: settlement finality, receivable assignment, working-capital advance, repayment priority, principal, expected return, counterparty exposure, collateral reservation, liquidity shortfall, transaction preflight, authorization validity, idempotent retry, state reconciliation, ledger consistency, contract invariant, database projection, evidence-backed delivery, review window, milestone release, default resolution, portable credit record, concentration risk, permission boundary and end-to-end traceability.

Do not say funded, paid, assigned, repaid or settled from a submitted hash or application log. Use submitted until the receipt succeeds and the expected transfer plus contract state are verified. Use projected for database state and authoritative for the relevant chain read. A mismatch is a reconciliation failure, not a cosmetic display problem.
